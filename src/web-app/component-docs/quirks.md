# Quirks — web-app

## Q-001: component-docs/ path deviation from Planifest convention

**Convention:** Planifest component docs should live at `src/{component-id}/docs/`.
**Reality:** `src/web-app/docs/` is the Vite HTML output directory (build artefacts — 10 generated `.html` files). Placing component `.md` docs there would coexist safely (Vite only bundles explicit HTML entry points), but would be confusing to developers.
**Resolution:** Component docs placed in `src/web-app/component-docs/` to clearly separate from build artefacts.

## Q-002: doc HTML files are build artefacts

`src/web-app/docs/*.html` files are generated by `scripts/build-docs.js` and must not be edited directly. Run `npm run build` or `node scripts/build-docs.js` to regenerate them. They are committed to the repo so Vite can bundle them, but are always overwritten on build.

## Q-003: location.reload() on theme toggle

`src/main.ts` forces a full page reload on theme toggle to re-render Mermaid SVGs in the new theme. This is a known workaround — Mermaid's SVG renderer is stateful and doesn't respond to CSS variable changes without re-initialisation.

## Q-004: Two-step process to add a new doc page

Adding a doc page requires: (1) add the `.md` source to `planifest-docs/`; (2) add the entry to `docs.manifest.json`. Missing step 2 causes the page to exist on disk but not appear in navigation. `build-docs.js` emits a warning when this happens.

## Q-005: Inline template vs external doc-template.html

`build-docs.js` supports both an inline template (hardcoded in the script) and an external `doc-template.html`. If `doc-template.html` exists at `src/web-app/doc-template.html`, it takes precedence. If using the external template, it must contain `{{DOC_NAV_LINKS}}` and `{{PREV_NEXT_NAV}}` placeholders — the script validates and exits if they are absent.
