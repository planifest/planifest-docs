# ADR-002 - Remove broken anchor links rather than adding pipeline sections

## Context

`planifest-docs/11-project-operations.md` contains two cross-reference lines at the bottom of the "Customising with planifest-overrides" and "Strict Orchestrator Mode" sections:

```
→ [Full directory structure and examples](03-pipeline.md#customising-with-planifest-overrides)
→ [Strict mode internals and ack file lifecycle](03-pipeline.md#strict-orchestrator-mode)
```

Neither `#customising-with-planifest-overrides` nor `#strict-orchestrator-mode` exist as headings in `03-pipeline.md`. The links are broken — they produce 404-equivalent navigation on the static site. The full content for both topics already exists on `11-project-operations.md` itself.

Two remediation paths were available: (A) add the missing sections to `03-pipeline.md`, or (B) remove the broken links.

---

## Decision

Remove the two broken cross-reference lines from `11-project-operations.md`. Do not add new sections to `03-pipeline.md`.

`03-pipeline.md` is "The Pipeline" — a reference for pipeline mechanics (phases, gates, artifacts, build log). It is not the correct home for project customisation and strict-mode internals, which are day-to-day operational concerns documented in `11-project-operations.md`. Adding these sections to `03-pipeline.md` would duplicate content, create a second source of truth, and produce drift every time either file is updated independently.

---

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|-------------|
| Add `#customising-with-planifest-overrides` and `#strict-orchestrator-mode` sections to `03-pipeline.md` | Cross-reference links start working; users can navigate from project-operations to deeper detail | Duplicates content already complete in project-operations; creates two sources of truth; increases maintenance burden; 03-pipeline.md's scope becomes blurred | Content is already complete where it lives; adding it elsewhere creates drift risk without user value |
| Remove the broken links (chosen) | No duplication; single source of truth; no maintenance burden | Users lose the promise of deeper detail (but there was no deeper detail — the links were always broken) | N/A — this is the chosen option |
| Replace broken links with correct anchors pointing back to headings on the same page | Self-referential links are navigable | Unusual pattern; adds no value since the user is already on that page reading the section | Minor improvement with no real benefit; removal is simpler |

## Consequences

**Positive:**
- No broken navigation on the published docs site
- Single source of truth for overrides and strict-mode documentation
- No future drift between two copies of the same content

**Negative:**
- The two sections no longer signal to readers that deeper detail exists elsewhere — but since the detail was never there, this is not a regression

**Risks:**
- A future contributor might add the missing sections to 03-pipeline.md independently, re-introducing duplication — mitigation: this ADR documents the intent; docs-agent can check for the sections at P6
