# ADR-001 - Introduce planifest-docs component manifest

**Skill:** planifest-adr-agent

**Component:** planifest-docs
**Status:** accepted

---

## Context

`src/web-app/component.yml` already declares `planifest-docs` in its `contract.consumes` list and states explicitly: "Must not own or modify planifest-docs markdown — that is the planifest-docs component's concern." However, no `src/planifest-docs/component.yml` exists. The planifest-docs content is a de-facto component with clear ownership boundaries, but it is not tracked by the Planifest framework — it has no manifest, no declared purpose, and no version.

This means:
- gate-write cannot enforce scope boundaries for planifest-docs writes without a declared component path
- There is no version history for the docs content component
- The implicit data ownership (planifest-docs owns markdown, web-app consumes it) is only documented in web-app's manifest, not in planifest-docs' own

---

## Decision

Create `src/planifest-docs/component.yml` to formally register planifest-docs as a Planifest component with type `content`, declaring its purpose, scope boundaries, and contract relationship with web-app.

This decision is consistent with the existing framework convention (every component that owns data or content should have a manifest) and resolves the gap identified when the gate-write hook blocked writes to `src/planifest-docs/` during this pipeline run.

---

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|-------------|
| Keep planifest-docs undeclared | No work required; docs content has always been written without a manifest | Leaves ownership implicit; gate-write cannot protect scope; no version tracking | Inconsistent with framework convention; the implicit relationship is already documented in web-app's manifest so formalising it is low cost |
| Add planifest-docs metadata to web-app's component.yml | Single manifest to maintain | Conflates two components with different responsibilities and different owners | Violates single-responsibility; web-app's manifest already explicitly disclaims ownership of planifest-docs content |

---

## Affected Components

| Component | Impact |
|-----------|--------|
| planifest-docs | Gains a manifest; writes to `src/planifest-docs/` are now gate-checked against declared scope |
| web-app | No functional change; `contract.consumes: planifest-docs` now has a corresponding manifest on the other end |

---

## Consequences

**Positive:**
- planifest-docs content ownership is now explicit and machine-readable
- gate-write can enforce scope boundaries for `src/planifest-docs/` writes in future pipeline runs
- Component versioning is now possible for the docs content

**Negative:**
- One more manifest to update when the docs component's scope changes
- Future agents must remember to bump `src/planifest-docs/component.yml` version after docs updates

**Risks:**
- The manifest version may drift from actual doc content state if future pipeline runs skip the component manifest update — mitigation: docs-agent checks component.yml at P6
