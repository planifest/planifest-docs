# ADR-001 - Doc file naming convention — NN-descriptive over pNNN-slug

## Context

The old `planifest-docs/` directory contained planning documents named with the `pNNN-` prefix convention (e.g. `p001-planifest-master-plan.md`). This naming was inherited from an internal planning doc system and was never intended for user-facing documentation. A full rewrite of the docs directory for v0.10 required choosing a naming convention for the 10 new user-facing pages.

---

## Decision

Use two-digit numeric prefix followed by a short descriptive slug: `01-overview.md`, `02-getting-started.md`, etc.

This convention makes the sort order explicit, the slug human-readable, and the output HTML URL (`01-overview.html`) clean and bookmarkable. The `pNNN-` prefix is retired with the old planning documents.

---

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|-------------|
| Keep `pNNN-` prefix | No changes to build script or nav link | Semantically misleading (p = planning doc, not user doc); awkward URL | Rejected — the `p` prefix communicates the wrong content type |
| Flat descriptive names (no prefix) | Cleanest URLs | No sort order; directory listing and nav order non-deterministic | Rejected — explicit sort order is needed for the 10-page sequence |
| Three-digit prefix `001-` | Consistent with legacy convention | Overkill for ≤10 docs; longer than needed | Rejected — two digits sufficient for anticipated doc count |

---

## Affected Components

| Component | Impact |
|-----------|--------|
| planifest-docs | All 10 new files use the new convention |
| src/web-app | `vite.config.ts` entry points updated; `index.html` and `build-docs.js` nav links updated |

---

## Consequences

**Positive:**
- URLs are human-readable and bookmarkable (`01-overview.html` vs `p001-planifest-master-plan.html`)
- Sort order is explicit and deterministic
- No semantic confusion between planning docs and user docs

**Negative:**
- Any external links to old `pNNN-` URLs will 404

**Risks:**
- See R-001 in risk register — assessed as low likelihood, accepted.
