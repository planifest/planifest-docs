# ADR-003 - Doc container max-width 1400px with 94% fluid width

## Context

The original `.doc-container` CSS used a narrow `max-width` that left large blank margins on wide monitors (reported by the user with a screenshot showing significant wasted horizontal space). Documentation pages benefit from wider layouts because they contain tables, code blocks, and Mermaid diagrams that are hard to read when column-wrapped.

---

## Decision

Set `.doc-container` to `max-width: 1400px` and `width: 94%`. This:
- Lets the container expand to 1400px on large monitors
- Shrinks fluidly to 94% of viewport on smaller screens without a fixed breakpoint
- Uses `clamp(1.5rem, 3vw, 3rem)` for horizontal padding so padding also scales with viewport

---

## Alternatives Considered

| Alternative | Pros | Cons | Why Rejected |
|-------------|------|------|-------------|
| Keep original narrow max-width | Comfortable line length for prose | Wastes screen real estate on wide monitors; tables and code blocks overflow or wrap awkwardly | Rejected — the user explicitly called this out as a problem |
| Full 100% width | Maximum use of space | Long prose lines become hard to read; no visual containment | Rejected — too wide for comfortable reading |
| Explicit media query breakpoints | Precise control per breakpoint | More CSS to maintain; `width: 94%` + `max-width` achieves the same outcome with less code | Rejected — unnecessary complexity |

## Consequences

**Positive:**
- Doc pages use available screen width on wide monitors
- Tables, code blocks, and Mermaid diagrams have more room
- Fluid `width: 94%` handles mobile and narrow viewports without a media query

**Negative:**
- Very long prose lines on ultra-wide monitors (>1400px) are avoided by the max-width cap, but 1400px is still wider than optimal prose line length (~65–80 chars). Users who prefer narrow prose may find it wide.

**Risks:**
- Low — pure CSS change, no functional impact.
