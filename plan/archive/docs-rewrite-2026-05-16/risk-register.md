## Risks

| ID | Category | Description | Likelihood | Impact | Mitigation | Status |
|----|----------|------------|------------|--------|-----------|--------|
| R-001 | technical | External links referencing old `pNNN-` doc URLs will 404 after rename to `NN-descriptive` naming. | low | medium | Old docs were internal planning files never linked from published content; no public URL canonicalisation existed. Accept the break — stale links to planning docs are not a regression. | accepted |
| R-002 | technical | `scroll-margin-top: 72px` is hardcoded to nav height. If nav height changes, headings will under- or over-scroll. | low | low | Nav height is stable (glass-nav with fixed padding). If nav height changes, the CSS value is a single-line fix. | accepted |
| R-003 | technical | `mermaid.run()` called with `startOnLoad: false` — if Mermaid adds breaking API changes, diagrams will silently fail to render. | low | low | Mermaid is a locked dev dependency. Breaking API changes are a semver-major event and would be caught during `npm install`. | accepted |
| R-004 | operational | `build-docs.js` must be run before `vite build`/`vite dev` to populate `src/web-app/docs/`. If skipped, the docs directory will be empty and Vite will emit entry-point errors. | medium | medium | `package.json` scripts chain `node scripts/build-docs.js && vite build` so the order is enforced. Dev server requires manual `npm run build-docs` first — document this in the README. | open |
| R-005 | technical | Doc content accuracy: 10 new pages written from framework source. If the framework source has gaps or ambiguity, doc pages may misrepresent behaviour. | medium | medium | Pages are grounded in `planifest-framework/` files read directly during authoring. A human review pass (P4 validation) is the final gate. | open |
