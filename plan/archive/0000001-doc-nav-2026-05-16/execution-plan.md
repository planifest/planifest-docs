# Execution Plan - 0000001-doc-nav

## Feature Summary
Retrofit the Planifest docs site to support manifest-driven navigation — a page order manifest drives top nav generation and prev/next injection, replacing hardcoded links. The homepage CTA 404 is fixed as part of this work.

## Non-Functional Requirements

| NFR | Target |
|-----|--------|
| Build time delta | < 5s added to existing build-docs.js runtime |
| New runtime dependencies | Zero |
| Backward compatibility | All existing doc pages rendered identically except for nav additions |
| Manifest validation | build-docs.js must fail loudly (process.exit(1)) if manifest is missing or malformed |

## Component Summary

| Component | Change type | Files affected |
|-----------|-------------|----------------|
| web-app | Extend existing | `scripts/build-docs.js`, `docs.manifest.json` (new), `index.html`, `src/style.css` (pagination styles) |

## Implementation Order

1. **REQ-001** — Create `docs.manifest.json` (no code dependency; foundational)
2. **REQ-004** — Fix CTA link in `index.html` (isolated; no dependency on manifest)
3. **REQ-002** — Extend `build-docs.js` for top nav injection (depends on REQ-001 manifest shape)
4. **REQ-003** — Extend `build-docs.js` for prev/next injection (depends on REQ-001 manifest shape; can be parallelised with REQ-002)

REQ-002 and REQ-003 are both changes to `build-docs.js` — implement sequentially in the same file to avoid merge conflicts.

## Data Flow

```
docs.manifest.json
      │
      ▼
build-docs.js
  ├── reads manifest (page order + titles)
  ├── generates {{DOC_NAV_LINKS}} → injects into every page template
  ├── for each page: injects <nav class="doc-pagination"> after content
  └── patches index.html CTA href if stale
      │
      ▼
src/web-app/docs/*.html  (build artefacts)
src/web-app/index.html   (patched in-place)
```

## Key Constraints
- `build-docs.js` is ESM (`"type": "module"` in package.json) — use `import`/`export`, not `require`
- Template may be loaded from `doc-template.html` or inline — code must handle both paths (already does)
- `dist/` is fully regenerated by `npm run build` — never patch dist/ directly
